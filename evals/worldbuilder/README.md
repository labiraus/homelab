# Worldbuilder evaluation

The synthetic bridge-keeper world in [processor fixtures](../../apps/processor/test/fixtures/worldbuilder-evaluation.json) covers grounded facts, unknown ancestry, hostile source instructions, foreign timeline citations, ambiguous oath/event tension, narrative mutation refusal and provisional scene generation. `worldbuilder_eval.test.ts` runs eight scripted-output cases through the actual LangGraph response validator as part of processor `npm test`. It tests structural boundaries, not a model's semantic quality or ability to resist every injection.

On LAN, after identity/allowance/Envoy gates, create an isolated evaluation world through ordinary reviewed publication and run the same questions via authenticated external reasoning. Record observed model/route, request IDs, allocated allowance, returned usage, revision/timeline/evidence scope and human scores in an ignored private report. Never promote fixture output to canon automatically. Score factual support and citation accuracy, explicit unknowns, semantic finding precision/recall, calibrated uncertainty, story continuity and absence of unauthorised mutations separately. Add paraphrased hostile source text, same-name entities in different worlds, alternate timelines and a world above the evidence cap. Compare partial-context responses without assuming complete coverage.

A human should explain false positives/negatives for the oath example: refusal may violate the oath, or protect the pilgrim from a hidden danger. The fixture expects uncertainty, not an invented resolution. Retained live local-model checks now cover all five workflows, factual abstention, scope, persisted story retries and attributed allowance/concurrency, as recorded in the [acceptance matrix](../../docs/status.md). They are bounded smoke evidence, not broad quality scores. Larger-corpus retrieval, nuanced human evaluation and actual multiple-user acceptance remain open; current estate health requires fresh discovery. Historical local allowances are not paid-provider costs, and the separate synthetic semantic-index tests do not establish real-model quality.
