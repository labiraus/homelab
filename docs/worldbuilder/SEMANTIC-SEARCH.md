# Optional canon semantic search

Canon now has an opt-in model/vector adapter used by external and the outbox projector. It is disabled in published defaults. The existing GET search remains a complete bounded lexical scan of authorized PostgreSQL canon, including historical snapshots. The retained document search pipeline and `embeddingutil` token hashes are separate implementations.

## Query and authority

`POST /api/worlds/{world}/search` accepts `{revision, timeline, query, at?, limit?, offset?, searchToken?}`. Revision must equal current canon; historical searches use GET. `at` accepts exact signed-int64 numeric tokens or decimal strings. Limit is 1–500 (default 100). Membership, timeline, query, page and current index readiness are checked before inference. Normal same-origin POST rules apply. A missing/stale projection returns 409; an unavailable projection returns 503 without reserving an attempt. An attempted embedding or vector-query failure returns 502 and retains its allowance charge.

The authorized snapshot supplies the entire visible ID set, filtered by timeline and half-open fictional time. OpenSearch applies those IDs plus exact world/revision/canon/profile filters before exact cosine scoring. It returns at most 100 IDs and scores; all text, metadata, calendars, review policy and citations come from PostgreSQL. Partial shard results, timeout, malformed/missing scores, wrong scope/profile, duplicate or hidden IDs, wrong ordering and incomplete candidate coverage are rejected. OpenSearch 3.9 sorted nested hits can have null `_score`; the adapter validates the explicit score/ID sort values rather than turning null into zero.

Hybrid ranking combines all canonical lexical matches and the top 100 vector candidates using reciprocal rank (constant 60), then record ID for ties. It can return records with no query-word match. `total` describes this combined candidate set, not every semantically relevant record. Responses identify `mode=hybrid`, `semanticProfile`, `semanticCandidates`, `discoveryStatus`, canonical citations and allocation provenance. A SHA-256 `searchToken` binds query, time, world/revision/timeline/profile and the ordered IDs. Continuations require that token; changed rankings return 409 and require a fresh first page. Each page is an explicit new metered POST, without automatic inference retries. The UI keeps submitted scope/token through load-more, advertises the allowance cost and uses lexical reads for save-triggered refreshes.

## Model and background projection

Both applications require the same `WORLDBUILDER_SEMANTIC_ENABLED=true`, `WORLDBUILDER_EMBEDDING_URL`, `WORLDBUILDER_EMBEDDING_MODEL`, `WORLDBUILDER_EMBEDDING_REVISION`, `WORLDBUILDER_EMBEDDING_DIMENSIONS` and optional `WORLDBUILDER_EMBEDDING_QUERY_PREFIX`. An optional `WORLDBUILDER_EMBEDDING_TOKEN` comes from a Secret. The URL is the fixed private gateway's complete `/v1/embeddings` route; requests never follow redirects. Model identity, every response index/vector/dimension and token usage are validated. There is no token-hash fallback or implicit model choice. The revision names immutable weights/tokenizer/pooling; the HTTP model name alone does not prove the deployed weights.

`apps/pkg/canonsearch` splits every UTF-8 byte of a record into at most 256-byte chunks without splitting runes, streams up to 32 records through model requests of at most eight chunks (matching the existing private TEI service), and forms a byte-weighted normalized mean of normalized vectors. Query chunks include the configured query instruction prefix. Records over 128 KiB, invalid UTF-8, zero/nonfinite vectors and invalid batches fail explicitly. This bounded mean representation is lossy; actual model quality requires its own gate.

The representation version, model, revision, dimensions and query prefix determine the profile and `worldbuilder-canon-vector-{profile}` index. One atomically replaced world document contains only canonical record IDs, content digests and vectors. Exact scoring uses a `knn_vector` mapping without an ANN index. Same-profile unchanged digests reuse vectors. External revision versions prevent stale events replacing new documents. A failed initial build may repeat completed inference batches because only a complete world document is published; it never publishes a partial snapshot.

The user authorized separate background limits: one batch at a time, at most 32 records. The projector serializes background projections across replicas using a PostgreSQL advisory transaction lock, while each embedder serializes its own batches. Published snapshots alone are read; source canon is unchanged. Projection has a 15-minute deadline, broker heartbeats every ten seconds, owning-database-session checks every second and retryable failure. Losing either owner cancels model work; actual database-session termination/recovery is covered by the disposable gate. Background model usage is logged with correlation/model/token/latency metadata, without narrative text. Background indexing does not consume the interactive per-user ledger. The intended service is the existing private CPU model, with no paid-provider charge.

On initial enablement or profile changes, run the existing explicit `WORLDBUILDER_REBUILD_ON_START=true` recovery path, then disable it after current revision coverage is verified. Earlier profile indexes are retained; configuration changes do not authorize their deletion. Live controller/route readiness and exact gateway access must be verified before activation.

## Interactive allowance and AI context

Standalone search reserves workflow `canon_search` in the existing durable inference ledger. The approved limits remain 100 requests per user per UTC day, two concurrent requests, £0.01 internal allocation per attempt and £1 per day across worlds/replicas. They are usage limits for local inference, not provider pricing. The immutable request hash binds normalized scope, page inputs and model profile. Failure/cancellation does not refund a reservation; completion uses its independent bounded database context.

When enabled and current, large-world AI context uses the same hybrid ranks and preserves mandatory rules/settings, requested references and visible reference closures within 100 evidence records. Small complete contexts need no embedding. Historical contexts remain lexical. Missing/stale/unavailable index readiness falls back to lexical context before inference and reports `semantic_unavailable_lexical_context`; an embedding attempt that fails aborts the charged workflow. A successful embedding plus generation is one existing workflow attempt, not an additional search charge. Its request hash binds the authorized request, deterministic initial evidence and semantic profile; final semantic evidence is recorded through citations/coverage, not by rewriting that hash. Trusted embedding usage overrides any model-supplied `retrieval` usage field. Combined retrieval/generation has a 50-second deadline, followed by at most five seconds for completion within the 60-second allowance lease; the dispatcher allows 60 seconds within its 90-second job lease.

## Configuration and acceptance

External/orchestrator chart values expose `worldbuilder.semantic`. Enabling requires explicit model/revision/dimensions; external also requires its existing positive AI allowance. The chart only accepts private cluster service embedding URLs and adds egress to the existing exact AI gateway Pod selectors/ports. It does not publish an embedding endpoint or enable a provider. Runtime activation, gateway identity enforcement, deployed immutable weights, realistic corpus quality/latency and production recovery remain unverified for this new canon feature.

Run the [owned canon-index gate](INDEX-ACCEPTANCE.md). It exercises actual PostgreSQL, JetStream and OpenSearch with a synthetic loopback HTTP embedding model. It proves semantic-only recall, scope/time isolation, canonical citations, metering including failures, large-context reference closure, changed-record reuse, stale-event refusal, profile drift refusal and reconstruction after full derived-index loss. The synthetic model proves integration and refusals; it does not establish real CPU model quality. Shared-client race tests separately cover malformed model responses, redirects, cancellation and full UTF-8 chunk coverage. UI tests cover explicit POST and submitted paging scope.

Local real-model smoke also passes (2026-10-12): pinned TEI CPU 1.9 and `BAAI/bge-large-en-v1.5` revision `d4aa6901d3a41ba39fb536a557fa166f842b0e09`, 1024 dimensions, with query prefix `Represent this sentence for searching relevant passages: `. An owned container had no network and mounted the existing model cache read-only. `TestPinnedCPUModelRepresentation` passes the real adapter contract, 32-record/eight-input batching, Unicode chunks and four paraphrase queries over nine canonical-shaped records. All four expected records rank first; cosine gaps are 0.0953, 0.0288, 0.0659 and 0.0760. An initial arbitrary 0.03-gap assertion rejected a correctly ranked result; the final smoke checks a unique expected top match and records gaps without interpreting them as calibrated confidence. This small fixture does not establish broad production relevance. The model container and local bridge were removed; the cache was preserved. Logs/checksums are retained in `.local/lan-recovery-20261011/canon-semantic-evidence/local-result.json`.

For a repeat with an independently verified owned model fixture, set `WORLDBUILDER_TEST_EMBEDDING_URL` to its loopback `/v1/embeddings` bridge, then run `go test -race -v -count=1 -run '^TestPinnedCPUModelRepresentation$'` from `apps/pkg/canonsearch`. Ordinary CI explicitly covers the synthetic adapter/index gate and skips this additional model smoke when no owned endpoint is supplied.
