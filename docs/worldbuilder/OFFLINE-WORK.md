## Storage follow-up evidence (2026-10-11)

The current archive tool sorts by timestamp/version ID and refuses equal timestamps. Boto3 exposes versions and delete markers in separate arrays; that representation alone cannot establish their relative order within a tied timestamp. The next implementation needs provider-verified listing/pagination evidence, retained and checked with the archive, rather than guessing from opaque version IDs. AWS documents newest-first version retrieval and key/version pagination in [ListObjectVersions](https://docs.aws.amazon.com/AmazonS3/latest/API/API_ListObjectVersions.html); verify the pinned source/target implementation before relying on wire order.

The existing [SeaweedFS smoke test](../../scripts/seaweedfs-smoke.py) completes a 5 MiB + 4 byte multipart object; it does not exercise archive import above 5 GiB. Add bounded streaming multipart imports, abort/uncertain-completion evidence and a real larger-than-5-GiB acceptance case. Part sizing must respect [S3 multipart limits](https://docs.aws.amazon.com/AmazonS3/latest/userguide/qfacts.html); AWS's current service limit is not evidence of SeaweedFS capacity. Preserve the orchestrator's version-map schema-1 resolver compatibility separately from any new archive evidence format.
