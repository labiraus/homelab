# Document search recovery

The October 2026 audit found zero models in ML Commons and zero documents in `rag-documents`. Processor readiness and creation of an ingest pipeline did not establish successful document processing: `rag-embedding-model` was only a placeholder ID. Do not start a broad source scan until actual model prediction and ingest simulation pass.

`helm/infra/embeddings` supplies a private CPU runtime for the existing 1,024-dimensional index. It pins Hugging Face Text Embeddings Inference's `cpu-1.9` image by digest and `BAAI/bge-large-en-v1.5` by model revision. The service has no public ingress or GPU allocation. Only the existing Envoy AI Gateway Pods can reach inference; its model-specific route shares the internal gateway with chat. The 5 GiB Longhorn claim caches reproducible model artifacts, not source documents or authoritative application state. Bootstrap now enables runtime deployment; model registration and document ingestion remain separate live gates.

The owned Docker runtime passes with UID/GID 1000, no capabilities, two CPUs and a 4 GiB limit: 1,024-dimensional normalized vectors, semantic separation (related cosine 0.8163 versus unrelated 0.2630), matching concurrent requests and oversized-input refusal. The observed warm memory is about 3.1 GiB, so the chart requests 4 GiB. TEI defaults to silent automatic truncation; explicitly pass `--auto-truncate false` and keep the long-input refusal check. The first model download took about eleven minutes in the fixture; retain the persistent cache and bounded cold-start allowance. These are local runtime results, not live gateway or ingestion acceptance.

The [TEI hardware guide](https://huggingface.co/docs/text-embeddings-inference/supported_models) documents the CPU image, and the [model card](https://huggingface.co/BAAI/bge-large-en-v1.5) describes the English model and its dimensions. The [OpenSearch ML inference contract](https://docs.opensearch.org/latest/ingest-pipelines/processors/ml-inference/) maps model input names to source fields and destination fields to model output paths; a payload-shape unit test alone does not verify those mappings.

Use `python3 scripts/validation/embedding-endpoint.py --base-url http://127.0.0.1:PORT/v1` with an owned forward to the runtime or gateway. It sends synthetic text only and checks the actual model identity, 1,024 finite normalized values, relevant versus unrelated retrieval, concurrent request isolation and oversized-input refusal. It does not register models, alter production documents or infer successful indexing from an HTTP health check.

The private gateway's chart now supplies a 256 KiB `ClientTrafficPolicy`, following the [upstream gateway example](https://github.com/envoyproxy/ai-gateway/blob/a693c3a1879321a886f3db80fead6cc1fecc7cf3/examples/basic/basic.yaml). The live gateway gate passes: eight-item batch 0.95 seconds, related/unrelated cosine 0.8163/0.2630, concurrent stable vectors and oversized-input refusal. The existing chat route passes and its model Pod UID is unchanged. Runtime readiness or a successful single vector alone would not have caught this failure.

Registration preserves existing trusted endpoint lists and adds only the anchored, escaped private embedding URL to both `plugins.ml_commons.trusted_connector_endpoints_regex` and `plugins.ml_commons.trusted_connector_private_endpoints_regex`, with `plugins.ml_commons.connector.private_ip_enabled=true`. The connector uses a fixed private URL, JSON content type and request body `{"input":"${parameters.input}","model":"${parameters.model}","encoding_format":"float"}`. Scalar input needs those quotes; the array-oriented upstream blueprint produced invalid JSON without them. Actual quoted/backslash/newline source simulation passes. ML Commons requires a nonempty credential map even for this unauthenticated private service; `{"local":"unused-private-runtime-placeholder"}` satisfies that storage requirement and is never sent in a header or body. It conveys no authority and contains no secret. Existing models must be undeployed before connector actions are changed, then redeployed and retested. Newly recreated OpenSearch clusters need fresh registration and corresponding model-ID configuration, not reuse of this ID without verification.

The operator acceptance command is `python3 scripts/validation/document-search.py --base-url http://127.0.0.1:PORT --model-id ID`, using an explicit owned forward to OpenSearch. It creates uniquely owned synthetic resources, generates pipeline and query payloads from the actual processor/shared Go implementation, and removes only its owned index/pipelines afterward. It checks prediction, dimensions, raw text coverage, scoped application filters and the semantic search pipeline. `--chunking-only` runs inline simulation without creating resources or invoking a model; it cannot establish successful inference or retrieval.

Live OpenSearch 3.9 simulation exposed two additional text failures: whole-document word analysis refuses more than 10,000 tokens, and native `fixed_char_length` can split a UTF-16 surrogate pair. The processor now first bounds text with a Unicode-safe Painless script, then applies native word splitting. Twelve simulation cases pass across zero/default/half overlap, including a 451,015-character document and emoji at chunk boundaries. Each chunk must be an exact source substring and together cover all source text through the final character. Both quoted raw strings and source-tail retention remain acceptance requirements.
