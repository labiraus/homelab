# Worldbuilder frontend

Apply `apps/AGENTS.md` and the root policy alongside these UI rules.

- Keep the existing React/Vite stack, shared light/dark tokens, authentication and hash routes. Supporting document routes remain available through the account menu. Close the world-creation menu after successful creation/selection so its overlay cannot obscure primary navigation.
- Keep header menu triggers in normal layout; position only the popup panel. Verify the trigger's rendered bounds before/after opening, Escape/focus return, outside dismissal and the Worlds destination at mobile widths. A working hash change to an empty landing page is not usable navigation. Ordinary accounts need an explanation when administration is unavailable.
- The real API browser launcher is `apps/external/worldbuilder/browser_test.go`, invoked through `scripts/worldbuilder/test-postgres.sh`; discover it before inspecting or changing integration setup. On Windows with Node 26, `NODE_OPTIONS=--no-experimental-webstorage` lets jsdom supply browser storage in component tests; Linux-installed `node_modules` must be reinstalled with the lockfile for Windows tooling.
- Use the correction brief and deployed audit in `docs/worldbuilder/`. Verify rendered document width and complete composer bounds at the specified viewports; DOM visibility or a successful auto-scrolling click does not prove containment. Reserve composer space in the pane and let the transcript scroll. Real software-keyboard acceptance requires a real device or equivalent device environment.
- Keep conversation cards mounted through section/thread navigation. Source lookup and story character selection retain the submitted revision/timeline/time or immutable story pin. A refreshed world revision must not silently rebase a candidate, manual draft or edited configuration.
- Drawers/sheets make the global header and other background branches inert, trap focus and restore the invoking control after inert state is removed. Avoid capturing the sheet's autofocus button as the return target.
- Use server-reported schema-9 capabilities for reviewed guides, Sandbox, structured scene state, shared conversations and progress delivery. Play/private context must never enter a shared thread. Shared requests retain stable IDs and exact pins; reconnect reads existing results instead of repeating inference. Use the schema-9 administrative policy instead of editable legacy canonical reviewPolicy.
- Offline Worldbuilder availability is separate from online document availability: keep authenticated device world routes after an offline restart. The account panel is `.auth-popover`; its expanded device controls need a bounded scroll area, including at mobile widths. Test actual hit targets, not only DOM visibility.
- IndexedDB saves must fail visibly on quota/storage errors. Commit queued story requests, provisional versions and monotonic ordering together; timestamps can tie and must not order dependent turns. Persist explicit saves before first delivery, including online saves when offline writing is enabled. Do not change queued payloads, pins or IDs; reconciliation creates new requests. Use the account-bound transactional lease before replay, and flush registered writing before activating a waiting service worker.

- Run `test:workspace` for local HTTP-fixture layout/journeys. `test:browser` selects only `worldbuilder.spec.js` and requires the disposable PostgreSQL/API harness. Keep these gates separate so fixture success cannot masquerade as real API acceptance or exhaust the bounded Go browser timeout. Update readable-label/disclosure expectations without weakening authorization, quorum, pin, privacy or conflict assertions.
- UI publication must run both workspace viewport/focus journeys and the disposable API browser gate. For deployed-asset checks, use `test:workspace` with `WORLDBUILDER_BROWSER_URL` pointing to an owned HTTP loopback forward; the workspace config rejects external hosts. Do not infer responsive acceptance from component tests or the API journeys alone. Reduced-height desktop Chromium checks are separate from a real mobile software keyboard.

- Finish the production build before starting any browser harness that serves `dist`. Never rebuild that directory while API/PWA browsers are running; Vite replaces assets and can serve an incomplete shell mid-journey. Independent read-only suites may share a completed build.

- Browser selectors for the world picker must use the exact combobox accessible name. A partial `getByLabel("Open world")` can also match the administration select through its nested “Reopen world” option, including during asynchronous route transitions. Retain actual API browser traces separately from workspace/PWA fixtures in CI.
